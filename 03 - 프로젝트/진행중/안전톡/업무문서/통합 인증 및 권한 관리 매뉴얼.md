### 1. JWT 설정 가이드

- 서비스 간 토큰 일관성을 위해 각 서비스의 `application.yml` 설정을 동일하게 관리합니다.

| 항목 | 설정값 | 역할 및 설명 |
| --- | --- | --- |
| **issuer** | `"awasoft”`  | 토큰 발급자 정보 (본 시스템 발행 여부 확인) |
| **accessToken.expireTime** | `10m` | **인증 토큰 수명**: 보안을 위해 10분 설정 |
| **refreshToken.expireTime** | `7d` | **갱신 토큰 수명**: 편의를 위해 7일 설정 |
| **secretKey** | `AWA...123!` | **서명 비밀키**: 32자 이상의 복잡한 키 (서비스 간 동일 필수) |

<aside>
💡

**주의**: `secretKey`가 백엔드와 프론트엔드 간 일치하지 않으면 토큰 해석이 불가능합니다.

</aside>

### 2. **JWT 상세 구조 및 서비스별 역할**

#### 2-1. **JWT Payload (Claims) 정보**

| **Claim Key** | **항목명** | **설명** |
| --- | --- | --- |
| **sub** | 로그인 ID | 사용자의 고유 계정 ID |
| **roles** | 권한 목록 | `ROLE_WEB_ADMIN` 등 할당된 권한 리스트 |
| **userId** | 사용자 ID | 시스템 내부 관리용 고유 PK |
| **userNm** | 사용자명 | 화면 표시용 성함 |
| **saftUserTypeCd** | 사용자 유형 | 업체관리자(G), 현장관리자(F), 근로자(W) |
| **prcgTypeCd** | 담당 구분 | 본사, 발주처, 감리, 현장 등 |
| **pobTypeCd** | 사업장 구분 | 원청(MAIN), 협력사(SUB) 등 |

### 5. 로그인 유효성 및 보안 검증 규칙

- 권한 할당 및 로그인 프로세스 완료 전, `AuthorityUtil`과 각 서비스의 필터/컨트롤러에서는 다음의 엄격한 보안 규칙을 적용하여 비인가 접근을 차단합니다.

#### **5-1. 사용자 상태 및 접속 경로 제한**

- **상태 코드 검증**: 사용자 상태가 `PENDING(승인대기)`, `DELETED(삭제)`, `LOCKED(잠금)`, `SUSPENDED(중지)`인 경우 모든 접속이 즉시 차단됩니다.
    - 특히 비밀번호 5회 오류로 인한 `LOCKED` 상태 사용자는 본인인증 전용 화면으로 리다이렉트됩니다.
- **접속 경로 제한**:
    - **근로자(W)**: 관리자용 `WEB` 서비스 로그인이 엄격히 제한됩니다.
    - **현장관리자(F)**: `WEB` 접속 시 권한은 부여되나, 보안 정책에 따라 **모바일 푸시 2차 인증**을 완료해야 실제 서비스 진입이 가능합니다.
- **앱 서비스 구분**: `MNG(관리자앱)`와 `WRK(근로자앱)`는 각 서비스에 허용된 사용자 유형(G, F vs W) 외의 접근을 차단합니다.

#### **5-2. 디바이스 보안 및 본인인증 (Mobile 전용)**

모바일 앱 접속 시 **1인 1기기 보안 원칙**을 준수하기 위해 디바이스 검증을 수행합니다.

- **기기 일치 검증**: 로그인 시 앱에서 전달된 기기 ID(`mblTelphDvcId`)가 DB에 저장된 정보와 다를 경우 로그인을 즉시 중단합니다.
- **본인인증 전환**: 기기 불일치 시 세션에 인증 정보를 임시 저장(`pendingAuthUser`)하고, 사용자를 본인인증 화면(`/user/login/dvcInfoView`)으로 리다이렉트합니다.
- **기기 정보 업데이트**: 본인인증 성공 시에만 DB의 기기 정보를 신규 기기로 업데이트하고 최종 로그인을 허용합니다.

#### **5-3. 사용자 유형별 가입 및 최초 로그인 절차**

- 사용자의 성격에 따라 관리자에 의한 등록 여부와 가입 방식이 다르게 정의됩니다.

| **항목** | **현장관리자 (FIELD)** | **근로자 (WORKER)** |
| --- | --- | --- |
| **로그인 전제 조건** | **관리자에 의한 사전 등록 필수**(업체/시스템 관리자가 WEB/APP에서 등록) | 사전 등록 없이 앱 설치 후 바로 로그인 시도 가능 |
| **첫 로그인 시도** | **서비스 이용 약관 동의** 및 기기 정보 등록 | **약관 동의 시 자동 회원가입** 처리 |
| **상세 프로세스** | 로그인 → 약관 동의 → 기기 정보 연동 → 로그인 완료 | 로그인 시도(미가입) → 약관 동의 → 가입 및 기기 등록 → 로그인 완료 |

<aside>
💡

**핵심 요약**

- **현장관리자**는 관리자가 먼저 등록해줘야 로그인이 가능하며, 앱 최초 진입 시 약관 동의를 거칩니다.
- **근로자**는 최초 로그인 시도 시 약관에 동의하면 즉시 가입 및 로그인이 완료되는 구조입니다.
- 모든 모바일 사용자는 기기 변경 시 반드시 본인인증을 통한 기기 갱신 절차를 밟아야 합니다.
</aside>
