# 01 화면을 만드는 두 방식

## 2.0: 서버가 HTML을 만든다 (Thymeleaf)

- 흐름
	1. 브라우저가 주소 요청
	2. Spring Controller가 데이터 조회
	3. Thymeleaf가 템플릿 + 데이터로 HTML 완성
	4. 완성된 HTML을 브라우저로 보냄
- 화면 이동마다 서버가 HTML을 새로 만듦
	- 페이지 전체가 새로 그려짐
- 화면 코드와 서버 코드가 한 프로젝트, 한 서버
	- 그래서 서버 하나만 띄우면 됨

## 2.5: 브라우저가 HTML을 만든다 (React)

- 흐름
	1. 브라우저가 주소 요청
	2. 거의 빈 HTML + JS 파일을 받음
	3. JS(React)가 브라우저 안에서 화면을 그림
	4. 데이터가 필요하면 JS가 API 호출 → JSON 받음
	5. 받은 JSON으로 화면 일부만 다시 그림
- 이 방식을 SPA(Single Page Application)라고 부름
	- HTML 파일은 하나, 화면 전환은 JS가 처리

## 프로젝트에서 보기

- `web/index.html`
	- 본문은 `<div id="root"></div>` 하나뿐
	- `<script type="module" src="/src/main.tsx">` 가 시작점
- `web/src/main.tsx`
	- `createRoot(document.getElementById('root'))` 로 root 안에 React 화면을 그림
	- 바깥을 감싸는 것들
		- `StrictMode`: 개발 중 실수 검사
		- `QueryClientProvider`: 서버 데이터 관리 ([[07 서버 데이터 - API 호출과 TanStack Query]])
		- `RouterProvider`: 주소별 화면 ([[06 화면 이동 - React Router]])

## 비교 정리

| 항목 | 2.0 Thymeleaf | 2.5 React |
|---|---|---|
| HTML 만드는 곳 | 서버 | 브라우저 |
| 서버가 주는 것 | 완성된 HTML | 화면용 JS 파일 + API의 JSON |
| 화면 이동 | 페이지 전체 새로고침 | JS가 바꿔 그림 |
| 백엔드 역할 | 화면 + 데이터 | 데이터(API)만 |
| 프로젝트 | 한 프로젝트 | `web/`(화면) · `back/`(API) 분리 |

- 핵심
	- 백엔드는 JSON만 주는 API 서버가 됨
	- 화면은 별도 프로젝트(`web/`)가 맡음
	- 그래서 서버가 둘로 나뉨 → [[02 서버가 왜 따로 뜨나]]
