#### 1. 4종류 메모리들에 대해서 가격, 용량, 속도로 관계를 설명하시오

| **메모리 종류** | **가격** | **용량** | **속도** |
| --- | --- | --- | --- |
| 보조기억장치 | 저렴 | 대용량 | 느림 |
| 메인 메모리 | 비쌈 | 몇 GB ~ 수십 GB | 빠름 |
| 캐시 | 매우 비쌈 | 몇 KB ~ 몇 MB | 매우 빠름 |
| 레지스터 | 무료 | 몇 바이트 ~ 몇 KB | 가장 빠름 |
- 보조기억장치는 하드 디스크 드라이브(HDD), 솔리드 스테이트 드라이브(SSD), 테이프 드라이브 등이 있습니다. 보조기억장치는 대용량의 데이터를 저장할 수 있지만, 메인 메모리나 캐시에 비해 속도가 느립니다.
- 메인 메모리는 랜덤 액세스 메모리(RAM)라고도 불리며, CPU가 직접 접근하여 데이터를 읽고 쓸 수 있는 메모리입니다. 메인 메모리는 보조기억장치에 비해 속도가 빠르지만, 용량이 제한적입니다.
- 캐시는 메인 메모리에 자주 사용되는 데이터를 저장하는 고속 메모리입니다. 캐시는 메인 메모리에 비해 속도가 훨씬 빠르지만, 용량이 매우 제한적입니다.
- 레지스터는 CPU 내부에 포함되어 있는 메모리로, CPU가 가장 빠르게 접근할 수 있는 메모리입니다. 레지스터는 매우 작은 용량이지만, 속도가 매우 빠릅니다.

#### 2. 클라우드 기술 이용 서비스 3가지에 대해서 설명하시오.

| **서비스** | **설명** |
| --- | --- |
| IaaS(Infrastructure as a Service) | 하드웨어, 네트워크, 스토리지 등을 필요한 만큼만 사용할 수 있도록 제공하는 서비스 |
| PaaS(Platform as a Service) | IaaS의 기능에 개발 플랫폼을 추가한 서비스 |
| SaaS(Software as a Service) | 소프트웨어를 인터넷을 통해 제공하는 서비스 |
- IaaS는 기업이 필요로 하는 하드웨어, 네트워크, 스토리지 등을 필요한 만큼만 사용할 수 있도록 제공하는 서비스입니다. 기업은 자체 데이터 센터를 구축하고 관리하는 비용을 절감할 수 있습니다. 또한, 최신 하드웨어와 소프트웨어를 빠르게 도입할 수 있습니다.
- PaaS는 IaaS의 기능에 개발 플랫폼을 추가한 서비스입니다. 기업은 개발에 필요한 도구, 라이브러리, 프레임워크 등을 사용할 수 있습니다. 따라서, 개발 비용을 절감하고 개발 시간을 단축할 수 있습니다.
- SaaS는 소프트웨어를 인터넷을 통해 제공하는 서비스입니다. 기업은 소프트웨어를 설치하거나 관리할 필요 없이, 인터넷만 연결하면 사용할 수 있습니다. 따라서, 유지 관리 비용을 절감하고, 언제 어디서나 소프트웨어를 사용할 수 있습니다.

#### 3. 버퍼링과 스플링에 대해서 설명하시오.

- **버퍼링**
    - 버퍼링은 입출력 장치의 속도 차이를 보완하기 위해 주기억 장치에 일시적으로 데이터를 저장하는 기술입니다.
    - 버퍼링은 주로 CPU와 입출력 장치 간의 속도 차이를 보완하기 위해 사용됩니다.
    - CPU는 입출력 장치에 비해 훨씬 빠른 속도로 데이터를 처리할 수 있습니다.
    - 따라서, CPU가 입출력 장치에서 데이터를 읽거나 쓰는 동안 대기하는 시간이 발생합니다. 버퍼링을 사용하면, CPU가 입출력 장치에서 데이터를 읽거나 쓰는 동안 다른 작업을 수행할 수 있습니다.
- **스플링**
    - 스플링은 Java 기반의 오픈 소스 프레임워크입니다. 스플링은 애플리케이션 개발의 다양한 측면을 지원합니다. 스플링은 다음과 같은 기능을 제공합니다.
    - **DI(Dependency Injection)**: 객체 간의 의존 관계를 외부에서 주입하는 기능입니다.
    - **AOP(Aspect Oriented Programming)**: 애플리케이션의 공통 기능을 모듈화하여 재사용성을 높이는 기능입니다.
    - **MVC(Model-View-Controller)**: 애플리케이션을 모델, 뷰, 컨트롤러로 분리하여 개발하는 디자인 패턴입니다.
    - **ORM(Object-Relational Mapping)**: 객체와 관계형 데이터베이스를 매핑하는 기능입니다.

#### 4. 교착상태의 해결 방법에 대해서 간단히 설명하시오.

교착상태는 프로세스가 서로 다른 프로세스의 자원을 요청하여 대기 상태에 빠져서 아무런 작업도 수행할 수 없는 상태를 말합니다. 

- **예방(prevention)**
    - 교착상태가 발생할 수 있는 조건을 제거하여 교착상태를 발생하지 않도록 하는 방법입니다. 교착상태의 발생 조건은 상호 배제(mutual exclusion), 점유와 대기(hold and wait), 비선점(no preemption), 순환 대기(circular wait)의 네 가지입니다.
    - 예방 방법은 이러한 네 가지 조건 중 하나 이상을 제거하여 교착상태를 발생하지 않도록 합니다.
- **회피(avoidance)**
    - 교착상태가 발생할 수 있는 상황을 미리 감지하여 교착상태를 회피하는 방법입니다.
    - 교착상태 회피 방법은 시스템의 상태를 지속적으로 모니터링하여 교착상태가 발생할 가능성이 있는 경우, 프로세스의 자원 요청을 제한하여 교착상태를 회피합니다.
- **탐지와 회복(detection and recovery)**
    - 교착상태가 발생한 후, 이를 탐지하여 회복하는 방법입니다.
    - 교착상태 탐지 방법은 시스템의 상태를 지속적으로 모니터링하여 교착상태가 발생한 경우, 이를 탐지합니다.
    - 교착상태 회복 방법은 교착상태에 빠진 프로세스를 강제 종료하거나, 자원을 할당하여 교착상태를 회복합니다.

#### 5. 최소작업 우선 스케줄링(SJF:Shortest Job First)에 대해서 설명하시오

**최소작업 우선 스케줄링(SJF:Shortest Job First)**은 CPU를 할당할 프로세스를 준비 큐에 있는 프로세스 중에서 남은 실행 시간이 가장 짧은 프로세스로 선택하는 방식의 CPU 스케줄링 알고리즘입니다.

**장점**

- **평균 대기 시간을 최소화할 수 있습니다.**

CPU를 가장 빨리 끝낼 수 있는 프로세스를 먼저 실행하면, 다른 프로세스들이 CPU를 기다리는 시간을 최소화할 수 있습니다. 따라서, 평균 대기 시간을 최소화할 수 있습니다.

- **짧은 작업을 먼저 실행하므로, 사용자의 반응 시간을 단축할 수 있습니다.**

사용자가 요청한 작업이 짧은 경우, SJF 스케줄링을 사용하면 사용자의 반응 시간을 단축할 수 있습니다.

**단점**

- **실행 시간이 정확하게 예측되지 않는 프로세스에 대해서는 효과적이지 않습니다.**

SJF 스케줄링은 프로세스의 실행 시간을 정확하게 예측해야 합니다. 그러나, 프로세스의 실행 시간은 다양한 요인에 의해 영향을 받을 수 있으므로, 정확하게 예측하기 어렵습니다. 따라서, 실행 시간이 정확하게 예측되지 않는 프로세스에 대해서는 효과적이지 않습니다.

- **프로세스의 실행 시간이 자주 변동하는 경우, 교착상태가 발생할 수 있습니다.**

SJF 스케줄링은 프로세스가 CPU를 할당받으면, 다른 프로세스가 CPU를 할당받을 때까지 CPU를 계속 사용할 수 있습니다. 따라서, 프로세스의 실행 시간이 자주 변동하는 경우, 교착상태가 발생할 수 있습니다.

**비선점형 SJF 스케줄링**

SJF 스케줄링은 크게 **비선점형**과 **선점형**으로 나눌 수 있습니다.

- **비선점형 SJF 스케줄링**은 프로세스가 CPU를 할당받으면, 다른 프로세스가 CPU를 할당받을 때까지 CPU를 계속 사용할 수 있습니다. 따라서, 프로세스의 실행 시간이 정확하게 예측되지 않는 경우에도 교착상태가 발생할 수 있습니다.

**선점형 SJF 스케줄링**

- **선점형 SJF 스케줄링**은 프로세스가 CPU를 할당받고 있는 도중에도, 다른 프로세스의 실행 시간이 더 짧은 경우, 해당 프로세스의 CPU 할당을 취소하고, 다른 프로세스에게 CPU를 할당할 수 있습니다. 따라서, 프로세스의 실행 시간이 정확하게 예측되지 않는 경우에도 교착상태를 방지할 수 있습니다.

**정리**

최소작업 우선 스케줄링은 평균 대기 시간을 최소화하고, 짧은 작업을 먼저 실행하여 사용자의 반응 시간을 단축할 수 있는 장점이 있습니다. 그러나, 실행 시간이 정확하게 예측되지 않는 프로세스에 대해서는 효과적이지 않으며, 프로세스의 실행 시간이 자주 변동하는 경우, 교착상태가 발생할 수 있다는 단점이 있습니다.

#### 6. 분산시스템이 미들웨어를 요구하는 이유를 설명하시오

분산 시스템은 서로 다른 컴퓨터, 네트워크, 하드웨어, 소프트웨어로 구성된 시스템입니다. 이러한 분산 시스템은 다음과 같은 특징을 가지고 있습니다.

- **분산성:** 분산 시스템은 서로 다른 컴퓨터, 네트워크, 하드웨어, 소프트웨어로 구성되어 있습니다.
- **자율성:** 분산 시스템의 각 구성 요소는 독립적으로 실행됩니다.
- **복잡성:** 분산 시스템은 다양한 구성 요소로 구성되어 있으므로 복잡합니다.

분산 시스템은 이러한 특징으로 인해 다음과 같은 문제에 직면합니다.

- **자원 관리:** 분산 시스템은 다양한 자원을 사용합니다. 이러한 자원을 효율적으로 관리해야 합니다.
- **통신:** 분산 시스템의 각 구성 요소는 서로 통신해야 합니다. 이러한 통신을 효율적으로 수행해야 합니다.
- **보안:** 분산 시스템은 다양한 위협에 노출되어 있습니다. 이러한 위협으로부터 시스템을 보호해야 합니다.

미들웨어는 이러한 문제들을 해결하기 위해 사용됩니다. 미들웨어는 분산 시스템의 각 구성 요소 사이에 위치하여, 다음과 같은 기능을 제공합니다.

- **자원 관리:** 미들웨어는 분산 시스템의 자원을 효율적으로 관리합니다. 예를 들어, 미들웨어는 프로세스 간 통신, 데이터베이스 접근, 파일 공유 등을 위한 자원을 관리합니다.
- **통신:** 미들웨어는 분산 시스템의 각 구성 요소 간의 통신을 효율적으로 수행합니다. 예를 들어, 미들웨어는 네트워크 프로토콜, 보안 프로토콜 등을 제공합니다.
- **보안:** 미들웨어는 분산 시스템을 다양한 위협으로부터 보호합니다. 예를 들어, 미들웨어는 인증, 권한 부여, 암호화 등을 제공합니다.

따라서, 분산 시스템은 다음과 같은 이유로 미들웨어를 요구합니다.

- **분산 시스템의 특징으로 인해 발생하는 문제를 해결하기 위해서**
- **분산 시스템의 효율성, 보안성, 확장성을 향상시키기 위해서**

#### 7. 다음 페이지 참조열에서에 페이지 부재가 몇  개 일어나지

(단, 페이지 프레임은 4개로 가정한다.)

페이지 참조열 0, 6, 5, 1, 4, 5, 0 , 3, 6, 5, 2, 3, 3, 2, 5, 3

페이지 참조열에서 페이지 부재가 발생하는 경우

- 0, 6, 5, 1, 4, 5, 0 : 0이 메모리에 없으므로 페이지 부재가 발생합니다.
- 0, 3, 6, 5, 2, 3, 3 : 3이 메모리에 없으므로 페이지 부재가 발생합니다.
- 2, 3, 5, 3 : 5가 메모리에 없으므로 페이지 부재가 발생합니다.

따라서, 총 3번의 페이지 부재가 발생합니다.

페이지 참조열에서 페이지 부재가 발생하는 경우는 다음과 같은 조건을 만족해야 합니다.

- 페이지 참조열에 있는 페이지 번호가 메모리에 없는 경우
- 페이지 참조열에 있는 페이지 번호가 메모리에 있지만, 다른 페이지가 대체되어야 하는 경우

위의 조건을 만족하는 경우는 총 3번입니다. 따라서, 총 3번의 페이지 부재가 발생합니다.

#### 8. 공개 OS와 상용 OS에 대해서 비교 설명하시오

**공개 OS**

- 누구나 무료로 사용할 수 있는 운영 체제
- 대표적인 공개 OS로는 리눅스, 윈도우즈 서버, 안드로이드 등

**상용 OS**

- 특정 기업이나 단체에서 개발하여 판매하는 운영 체제
- 대표적인 상용 OS로는 마이크로소프트 윈도우, macOS, iOS 등

**차이점**

| 구분 | 공개 OS | 상용 OS |
| --- | --- | --- |
| 소유권 | 소유권이 없음 | 특정 기업이나 단체가 소유함 |
| 가격 | 무료 | 유료 |
| 개발 | 다양한 개발자가 참여하여 개발됨 | 특정 기업이나 단체에서 개발됨 |
| 지원 | 커뮤니티에서 지원됨 | 기업이나 단체에서 지원됨 |
| 보안 | 보안 취약점이 발견되면 빠르게 패치됨 | 보안 취약점이 발견되면 패치되기까지 시간이 걸릴 수 있음 |
| 확장성 | 다양한 커스터마이징이 가능함 | 특정 기업이나 단체의 정책에 따라 커스터마이징이 제한 될 수 있음 |

**공개 OS의 장점**

- 가격이 저렴함
- 소유권이 없으므로 누구나 자유롭게 사용할 수 있음
- 개발에 다양한 개발자가 참여하여 안정성이 높음
- 커뮤니티에서 지원을 받을 수 있어 유지 보수가 쉽음

**공개 OS의 단점**

- 보안 취약점이 발견되면 빠르게 패치되지 않을 수 있음
- 상용 OS에 비해 기능이 제한될 수 있음

**상용 OS의 장점**

- 가격이 비싸지만, 안정성과 기능이 뛰어남
- 기업이나 단체에서 지원을 받을 수 있어 유지 보수가 쉽음
- 보안 취약점이 발견되면 빠르게 패치됨

**상용 OS의 단점**

- 가격이 비쌈
- 소유권이 있으므로 특정 기업이나 단체의 정책에 따라 사용이 제한될 수 있음
- 커스터마이징이 제한될 수 있음

#### 9. 알고 있는 운영체제의 종류와 간단한 설명을 쓰시오

대표적인 컴퓨터 운영체제로는 윈도우(Windows), 맥 OS(Mac OS), 리눅스(Linux), 유닉스(Unix) 등이 있습니다.

| **운영체제** | **종류** | **특징** |
| --- | --- | --- |
| 윈도우 | 상용 | 개인용, 그래픽 UI, 다양한 응용 프로그램 지원 |
| 맥 OS | 상용 | 개인용, 유닉스 기반, 안정성, 보안 |
| 리눅스 | 공개 | 다양한 하드웨어, 유닉스 기반, 안정성, 보안 |
| 유닉스 | 상용 | 서버, 슈퍼컴퓨터, 임베디드 시스템, 멀티태스킹, 멀티유저, 네트워킹 |
