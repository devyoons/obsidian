### 🧐컬렉션(collection)

**컬렉션(Collection)** : 여러 객체(데이터)를 모아 놓은 것을 의미

**프레임웍(framework)** : 표준화, 정형화된 체계적인 프로그래밍 방식

**컬렉션 프레임웍** 

- 컬렉션(다수의 객체)을 다루기 위한 표준화된 프로그래밍 방식
- 컬렉션을 쉽고 편리하게 다룰 수 있는 다양한 클래스를 제공
    - 객체를 저장, 삭제, 검색, 정렬 → 다수의 데이터
- java.util패키지에 포함. JDK1.2부터 제공

**컬렉션 클래스(coolection class)**

- 다수의 데이터를 저장할 수 있는 클래스(ex . ArrayList, HashSet)

### 🧐스택과 큐(stack & queue)

**스택 (Stack)** : `LIFO 구조`. 마지막에 저장된 것을 제일 먼저 꺼내게 된다. ex) 상자

**큐 (Queue) :** `FIFO구조`. 제일 먼저 저장한 것을 제일 먼저 꺼내게 된다. ex) 줄서기

- **Stack & Queue 기본코드예제**
    
```java
public static void main(String[] args) {
		Stack st = new Stack();
		Queue q = new LinkedList();	// Queue인터페이스의 구현체인 LinkedList를 사용
		
		st.push("0");
		st.push("1");
		st.push("2");

		q.offer("0");
		q.offer("1");
		q.offer("2");

		System.out.println("= Stack =");
		while(!st.empty()) { // 비어있지 않으면 
			System.out.println(st.pop()); // 스택에서 요소 하나를 꺼내서 출력
		}

		System.out.println("= Queue =");
		while(!q.isEmpty()) { // 비어있지 않으면
			System.out.println(q.poll()); // 큐에서 요소 하나를 꺼내서 출력
		}
	}
}

//결과
= Stack =
2
1
0
= Queue =
0
1
2
```


#### 스택과 큐의 활용

**스택의 활용 예**

- 수식계산 **((3+2)*8)/2**
- 수식괄호검사  **((3+2)*8)/2 -** 괄호열고(push) 닫은(pop) 개수 일치 확인
- 워드프로세서의 undo/redo **작업취소 되돌리기**
- 웹브라우저의 뒤로/앞으로

**큐의 활용 예** 

- 최근사용문서
    - 최근사용한 문서 목록을 보여주는데 이때 새로운 목록이 추가될 때 제일 오래된 목록삭제함
- 인쇄작업 대기목록
- 버퍼(buffer)

- **Stack & Queue 예제**
    
```java
Stack st = new Stack();
		String expression = "((3+5)*8-2)";

		System.out.println("expression:" + expression);

		try {
			for (int i = 0; i < expression.length(); i++) { //for문을 이용해서
				char ch = expression.charAt(i);               // 하나씩 꺼내기

				if (ch == '(') {
					st.push(ch + "");       // '(' 넣어주고
				} else if (ch == ')') {   // ')'꺼내주고 개수가 맞다면 stack이 비어있어야함
					st.pop();
				}
			}

			if (st.isEmpty()) {
				System.out.println("괄호가 일치합니다.");
			} else {
				System.out.println("괄호가 일치하지 않습니다.");
			}
		} catch (EmptyStackException e) {
			System.out.println("괄호가 일치하지 않습니다.");
		}
//결과
expression:((3+5)*8-2)
괄호가 일치합니다.
```

- 위 예제는 수식계산에 여는괄호를 ‘(’ 담아주고  닫는괄호 ‘)’가 있으면 꺼내서 괄호를 확인하는것
- 개수가 일치하지 않으면 예외가 발생함 → 비어있지 않는다는 예외  EmptyStackException

### 🧐Linked List : 연결기반(불연속)

- 연결 리스트는 크기가 동적인 자료구조이다.
- 각 데이터들을 포인터로 연결하여 관리하는 자료구조
- ‘노드’라는 객체로 이루어져 있다.

![[02 - 학습/KH 교육과정 2022/수업 필기/JAVA 이론/첨부/2d20eb1c_Untitled.png]]

1. **데이터 영역** : 데이터를 저장
2. **포인터 영역** : 다음 데이터가 저장된 노드를 가리키는 포인터 영역

3. **전 노드를 가리키는 포인터 영역** : 이중 연결 리스트 일 때

- `head` : 첫 노드를 가리킨다
- `tail` : 마지막 노드를 가리킨다
- `_size` : 노드의 개수

#### LinkedList - 배열의 장단점

![[02 - 학습/KH 교육과정 2022/수업 필기/JAVA 이론/첨부/8264f881_Untitled.png]]

- **장점**
    - **배열은 구조가 간단하고 데이터를 읽는 데 걸리는 시간 (접근시간,access time)이 짧다.**
- **단점**
    - **크기를 변경할 수 없다.**
        - 크기를 변경해야 하는 경우 새로운 배열을 생성 후 데이터를 복사해야함 ****
        - 크기 변경을 피하기 위해 충분히 큰 배열을 생성하면, 메모리가 낭비됨
    - **비순차적인 데이터의 추가, 삭제에 시간이 많이 걸린다.**
        - 데이터를 추가하거나 삭제하기 위해, 다른 데이터를 옮겨야 함.
        - 그러나 순차적인 데이터 추가(끝에 추가)와 삭제(끝부터 삭제)는 빠르다.
        

#### LinkedList - 배열의 단점을 보완

![[02 - 학습/KH 교육과정 2022/수업 필기/JAVA 이론/첨부/9db7faa7_Untitled.png]]

- 배열과 달리 링크드 리스트는 불연속적으로 존재하는 데이터를 연결(link)
    - **데이터의 삭제** : 단 한번의 참조변경만으로 가능 , **변경에 유리**
    - **데이터의 추가** : 한번의 Node객체생성과 **두 번의 참조변경만으로 가능**

#### 이진 탐색 트리(binary search tree)

- 부모보다 작은 값은 왼쪽, 큰 값은 오른쪽에 저장
- `단점 : 데이터가 많아질 수록 추가, 삭제에 시간이 더 걸림(비교 횟수 증가)`
- 위와 같이 트리를 구성하게 되면 왼쪽 마지막 레벨이 제일 작은 값이 되고 오른 쪽 마지막 레벨의 값은 제일 큰 값이 된다
- 그러나 컴퓨터는 알아서 값을 비교하지 못하기 때문에 기준이 필요하다.**TreeSet에 저장되는 객체가 Comparable을 구현하거나 TreeSet에게 Comparator를 제공하여 두 객체를 비교할 기준을 알려주어야 한다.**
- 저장된 값의 개수에 비례해서 검색시간이 증가하지만 검색 효율이 뛰어난 자료구조이다.즉, 노드의 추가 및 삭제에 시간이 걸리지만 검색과 정렬에는 유리하다.
- TreeSet은 값을 저장할 때 이미 정렬이 되어있어 별도의 정렬작업이 필요없다.

		System.out.println("50보다 작은 값 :" + set.headSet(50));//컴파일러->오토박싱
		System.out.println("50보다 큰 값 :"  + set.tailSet(new Integer(50)));
		System.out.println("40과 80사이의 값 :" + set.subSet(40, 80));
	}
}

#### 트리 순회(tree traversal)

- 이진 트리의 모든 노드를 한번씩 읽는 것을 트리 순회라고 함.
- 리스트나 스택, 큐와 같은 선형 자료구조와 다르게 트리는 계층구조라서 여러 순회 방법이 있다.

![[02 - 학습/KH 교육과정 2022/수업 필기/JAVA 이론/첨부/0ad04d76_Untitled.png]]

- **전위순회(preorder)**
    
    ⇒ 루트 노드(Root)부터 방문해 순회하는 방식
    
    ⇒ Root → Left → Right
    
    ⇒ 진행 방향 : `80` → `50` → `35` →`10` → `45` → `65` → `95` → `100`
    
- **후위순회(postorder)**
    
    ⇒ 하위 트리를 모두 방문 후 루트 노드(Root)를 방문해 순회하는 방식
    
    ⇒ Left → Right → Root
    
    ⇒ 진행 방향 : `10` → `45` → `35` → `65` → `50` → `100` → `95` → `80`
    
- **중위순회(inorder)** : `오름차순정렬`
    
    ⇒ 왼쪽 하위 트리 방문 후 루트 노드(Root)를 방문해 순회하는 방식
    
    ⇒ Left → Root → Right
    
    ⇒ 진행 방향 : `10` → `35` → `45` → `50` → `65` → `80` → `95` → `100`
    
- **레벨순회** : 한층씩 읽는것.

#### Comparable

`Comparable`은 `Java.lang` package에 있는 `인터페이스`이며 정렬을 위해 사용되는데,

#### Comparator

`Comparator`는 `Java.util` package에 있는 인터페이스.

`Comparable`과 마찬가지로 `Comparator`는 객체의 정렬에 사용됨

하지만 `Comparator`의 구현체는 클래스 자체가 정렬기준으로 사용된다. 

→ `외부 정렬기준`을 정의한다는 것

데이터를 정렬하고 싶다면  Comparator를 구현한 외부 정렬자를 사용하는 것

`Comparable`인터페이스를 구현할 때와 차이점 알기

외부 정렬자(Comparator의 구현체)를 사용할 때는 `Collections.sort()`의 매개변수로 정렬기준을 넘겨주어야 하는데 이때 Comparator의 구현체에서는 매개변수를 2개 넘겨줘야한다.

그리고 `Comparator`의 구현체는 `compare(Student s1, Student s2)`메서드를 구현하는데 매개변수가 2개여야한다. 

현재 자기자신의 값과 비교하는 compareTo메서드와 다르게 매개변수로 받은 2개의 객체가 가진 값을 비교하기 때문!

이미 오름차순으로 정렬기준이 잡혀있는 comepareTo메서드의 결과에 -1을 곱하면 내림차순으로 쉽게 구현할 수 있다.

이처럼 이미 정해진 정렬기준 외 다른 정렬기준을 사용하고 싶다면 `Comparator`의 구현체를 사용하여 여러가지 정렬기준을 사용할 수 있다.
