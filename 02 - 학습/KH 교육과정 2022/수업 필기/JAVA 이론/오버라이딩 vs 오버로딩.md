### 🧐메소드 오버라이딩 : Method Overriding

오버라이딩은 메소드의 이름이 서로 같고, 인자와 반환형이 같은 경우

상속받은 메소드를 덮어쓰는 것을 말한다. (부모의 메소드를 재정의 하는 것!)

- 상속관계에 있는 부모 클래스에서 이미 정의된 메소드를 자식 클래스에서 **같은 시그니쳐**를 갖는 메소드로 다시 정의하는 것!

'부모 클래스의 기존 메소드는 무시해버리고 자식 클래스의 메소드의 기능을 사용하겠다'는 의미와 같다.

자식 클래스는 부모 클래스의 private 멤버를 제외한 모든 메소드를 상속받는다. 

**조건**

1. 오버라이딩이란 동작만 재정의하는 것이므로, 메소드의 선언부는 기존 메소드와 같아야 한다.
**but.**
   메소드의 반환타입이 부모 클래스의 반환타입으로 **"타입 변환"**할 수 있다면 변경할 수 있다.
2. 부모 클래스의 메소드보다 접근 제어자를 더 좁은 범위로 변경할 수 없다.
3. 부모 클래스의 메소드보다 더 큰 범위의 예외를 선언할 수 없다.
    - 하지만 메소드의 반환 타입은 부모 클래스의 반환 타입으로 타입 변환할 수 있는 타입이라면 변경할 수 있다.
4. `private메서드`는 Override 자체가 **안됨**. (같은 클래스가 아니기 때문에)
5. `final메서드`는 오버라이드가 **불가**하다.
6. 부모메서드가 던지는 예외를 제거하거나 한정할 수 있다.
    - 부모 클래스의 메소드보다 더 큰 범위의 예외를 선언할 수 없다.
7. 오버라이드한 부모메서드는 `super키워드`를 통해 **호출 할 수 있다**.

- **메소드 오버라이딩 시 사용되는 애노테이션 `@Override`**
    - 컴파일 시점에 정말 오버라이드가 되는 것이 맞는지 check 해주는 역할을 해준다.
    - 개발자의 실수를 줄일 수 잇다는 것,
    
    또한, 명시적으로 Override를 표현함으로써 가독성에 이점을 가져갈 수 있다. 
    
    **즉, 오버라이딩 시 @Override 애노테이션을 명시적으로 표현하도록 한다.**

#### 추상메서드 인터페이스

- 인터페이스와 추상클래스

**추상메서드**

**정의**

내용이 없는 메서드, 구현(정의)는 하지 않고 선언만 한 메서드

**목적**

메서드의 내용이 너무 일반적인 내용이라, 부모 클래스에서 구체화하여 정의할 필요가 없을 경우, 추상메서드로 선언만하고 상속받은 자식 클래스에서 재정의하도록 할 때 사용

**추상클래스(abstract class)**

**정의**

- 한 개 이상의 추상 메서드를 가지는 클래스
- 일반적인 클래스는 세부적이고 구체적
- 반면 추상클래스는 일반클래스에 비해 구체적이지 않고 추상적

**목적**

- 추상 메서드는 선언만되고 구현이 되지 않는 불완전한 클래스임으로 객체로 생성되어서는 안된다.
- 이런 클래스(추상 메서드가 포함된 클래스)는 추상 클래스로 선언하여 객체 생성을 금지시킨다.

**추상클래스는 IS -A "~이다."**

**추상클래스는 반드시 하나 이상의 추상 메서드를 가지며, 객체를 생성할 수 없다.**

**하지만, 슈퍼클래스로 사용할 수는 있으며 추상 메서드를 사용하기 위해서는 반드시 해당 메서드를 오버라이딩(재정의)해야 한다.**

추상 클래스 또는 추상 메서드를 선언하기 위해서는 "abstract" 키워드를 사용한다.

```java
abstract class 클래스명{
	추상 메서드();
}
```

```java
abstract 접근제한자 반환타입 메서드명(매개변수...){
	//실행코드
}
```

**추상 클래스와 추성 메서드 코드 예**

```java
// 추상메서드를 포함함으로 추상 클래스로 선언한다.
abstract class Cat{
	abstract void call();   // 추상 메서드로서 선언부만 존재한다. (구현은 구현체에서)
	void call2(){
		System.out.println("일반 메서드");
	}
}

class FirstCat extends Cat{
	void call(){
		System.out.println("첫번째 냥");
	}
}

class SecondCat extends Cat{
	void call(){
		System.out.println("두번째 냥");
	}
}

public class AbstractTest{
	public static void main(String[] args){
		FirstCat fc = new FirstCat();
		SecondCat sc = new SecondCat();
		
		fc.call();
		sc.call();
	}
}

////////
첫번째 냥
두번째 냥
```

** 

추상 메서드를 재정의 하지 않는 경우 컴파일에러가 발생된다.

그러므로 추상메서드는 반드시 재정의 되도록 가이드하는 방법으로 활용할 수 있다.

추상 : 무엇인가 덜 구체화 된 것

객체 : 상태와 행동을 가진 것

클래스 : 객체를 만들기 위한 틀

초기화 : 클래스를 이용해 객체를 생성

**Q.** 왜 자체적으로 인스턴스를 생성하지도 못하고 시그니쳐만 있는 메소드를 왜 만들어서 상속을 강제적으로 받고 오버라이딩을 해야하는 것일 까?

- 작은 프로젝트에서는 추상 클래스를 사용하는 일은 거의 없을 것이다.
- 프로젝트가 커지면 여러 개발자들이 참여하게되는데 이때 공통적으로 작성되어야 할 내용들이 있을 것이다.
→ 이 경우 개발자들마다 네이밍을 다르게 정의한다면 유지보수 및 관리 등 문제가 발생할 것이다.
- 공통된 내용(필드나 메소드)들을 추출하여 통일된 내용으로 작성하도록 규격화 하는 것이다.
- 또한, 공통된 필드나 메소드들을 가지게되는 유사한 클래스들이 생성되는 것을 방지하여 공통적인 것들을 추상 클래스로서 정의하여 확장할 수 있도록 하게 한다.
- 이는 추상 클래스를 상속받아 구현한 구현체에 대해 확장성을 제공하고 공통적인 부분을 관리하게 됨으로써 재사용성과 유지보수성을 높일 수 있고 가독성 또한 높일 수 있다.

#### 인터페이스

- 추상 클래스와 비슷한 기능을 하지만 극단적인 경우이다.
- 추상메서드와 상수로만 이루어져 있다. (로직을 작성할 수 없다.)
- 다중 상속이 가능하다.

**인터페이스는 HAS - A "~을 할 수 있는".**

```java
interface 인터페이스명{
	public abstract void 추상메서드명1();    // public abstract 키워드는 생략 가능하다.
	void 추상메서드명2();
}
```

```java
class 클래스명 extends 상속받을 클래스명 implements 인터페이스명 {
	// 구현
}
```

```java
interface CatWorld{
	public void call();
}

public class InterfaceTest impelements CatWorld{
	public void call(){
		System.out.println("냥");
	}
}
```

**

클래스에 인터페이스 상속 시 인터페이스 내 정의된 **모든 추상 메서드를 구현(오버라이드)**해야만 정상적인 컴파일이 가능하다.

**인터페이스와 추상클래스의 공통점**

1. 추상 클래스와 인터페이스는 선언만 있고 구현 내용이 없다.
2. 자기 자신이 new 키워드를 통해 객체를 생성할 수 없으며, 상속받은 자식만이 생성 가능하다.
3. 상속받은 자식이 구현을 반드시 하도록 해야 할 때 사용할 수 있다.

**인터페이스와 추상클래스의 차이점**

**

인터페이스를 상속받는 클래스는 반드시 인터페이스에 있는 메서드를 다 구현해야 하지만,

추상클래스를 상속받는 클래스는 추상 메서드만 구현하고 일반메서드는 사용하지 않아도 상관없다.

**추상 클래스의 사용 시기**

- 상속 관계를 쭉 타고 올라갔을 떄 같은 조상 클래스를 상속하는데 기능까지 완벽히 똑같은 기능이 필요한 경우

**인터페이스 사용 시기**

- 상속 관계를 쭉 타고 올라갔을 때 다른 조상 클래스를 상속하는데 같은 기능이 필요한 경우 인터페이스 사용

#### 🔻추상메소드

- abstract 키워드를 사용한다.
- 메소드 몸통이 없다
- 추상클래스 안에서만 정의될 수 있다.

```java
package kh.java.polymorphism.animal;

public abstract class Animal {
	
	public abstract void say();
	
	public void attack() {
	};
	
}
```

```java
package kh.java.polymorphism.animal;

public class Lion extends Animal {

	public void kick() {
		System.out.println("라이언 킥을 날렸습니다.");
	}
	
	@Override
	public void attack() {
		kick();
	}
	
	@Override
	public void say() {
		System.out.println("안녕하세요. 라이언입니다.");
	} //이때 say 메소드가 없다면 에러가 난다.

}
```

```java
package kh.java.polymorphism.animal;

public class Tiger extends Animal {

	public void punch() {
		System.out.println("호랑이 펀치를 날렸습니다.");
	}
	
	@Override
	public void attack() {
		punch();
	}
	
	@Override
	public void say() {
		System.out.println("안녕하세요. 타이거입니다.");
	}//이때 say 메소드가 없다면 에러가 난다.

}
```

### 🧐오버로딩과 오버라이딩

**오버로딩** : 새로운 메소드를 정의하는 것

- 두 메서드가 **같은 이름**을 갖고 있으나 **인자의 수나 자료형이 다른 경우**
