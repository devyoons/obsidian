# 강의: 제네릭스(Generics)

## 강의 내용

---

---

#### 🧐제네릭스(Generics)

<aside>
❓ 제네릭스는 JDK 1.5에서 처음 도입됨

</aside>

제네릭스는 다양한 타입의 객체를 다루는 메서드나 컬렉션 클래스에

**컴파일 시의 타입 체크 `(compile - time type check)`를 해주는 기능**이다.

→ 객체의 타입을 컴파일 시에 체크하기 때문에 **객체의 타입 안정성을 높이고 형변환의 번거로움이 줄어든다.**

**타입 안정성을 높인다?**

의도하지 않은 타입의 객체가 저장되는 것을 막고, 저장된 객체를 꺼내올 때 원래의 타입과 다른 타입으로 잘못 형변환 되어 발생할 수 있는 오류를 줄어준다는 것

**장점**

1. **`타입 안정성을 제공한다.`**
→ 컴파일 타임에 타입 체크를 하기 때문에 런타임에서 ClassCastException과 같은 
    UnchekedException을 보장받을 수 있다.
2. 타입체크와 **`형변환을 생략`**할 수 있으므로 코드가 간결해진다.
→ 해당 타입의 요소만 추가가능하고 꺼내올때도 해당타입을 리턴하므로 형변환은 생략가능

---

#### 🧐제네릭을 사용하는 이유

- 컴파일 시 **강한 타입 체크**를 할 수 있다.

    - 컴파일러는 **코드에서 잘못 사용된 타입 때문에 발생하는 문제점을 제거**하기 위해
         제네릭 코드에 대해 강한 타입 체크를 한다.

    - 실행 시 타입 에러가 나는 것보다 컴파일 시에 미리 타입을 강하게 체크해서 에러를 사전에 방지

- **타입 변환(casting)을 생략**해도된다.

    - 타입을 국한하기 때문에 요소를 찾아올 때 **타입 변환을 할 필요가 없어** 프로그램 성능향상효과

---

#### 🧐제네릭 사용법

<aside>
❓ 제네릭 타입은 **`클래스와 메서드에 선언할 수 있다`**. 
하지만 static자원(필드/메소드)에는 클래스레벨의 제네릭 타입변수를 사용할 수 없다.

</aside>

**자주 사용하는 타입변수(인자)** → 다른 것을 사용해도 되지만 상황에 맞게 의미있는 문자를 사용

| 타입변수 | 설명 |
| --- | --- |
| <T> | Type |
| <E> | Element |
| <K> | Key |
| <V> | Value |
| <N> | Number |
| <R> | Result |

**제네릭** **시그니처**

```java
public class 클래스명<T> {...}
public interface 인터페이스명<T> {...}
public static <T> 클래스명<T> 메소드명(T 변수명){...}
```

1. **타입 파라미터`<T>`를 사용한다** 
     →클래스 설계 시 구체적인 타입을 명시할 필요가 없어 타입 변환을 최소화 시킨다.

![[02 - 학습/KH 교육과정 2022/수업 필기/JAVA 이론/첨부/9f085782_Untitled.png]]

Box 클래스의 타입을 Integer로 구체화 → 꺼낼 때도 형변환이 필요 없다.

- 위 코드처럼 **`구체적인 타입으로 객체를 생성`**하면 타입파라미터 T 가 **Integer , String으로 변환**되어 set(), get()으로 저장된 필드를 읽어올 때 **`타입 변환이 필요없다.`**

1. **`명시적 지역타입변수 선언`**과 **`암묵적 지역타입변수 추론`**이 있다.
