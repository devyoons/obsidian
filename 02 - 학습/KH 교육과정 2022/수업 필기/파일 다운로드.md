### Servlet : BoardFileDownloadServlet

---

- 기존 요청은 HTML을 전달했지만 이번엔 파일을 전달해야함.
- 파일은 서버에 있지만 실제로 저장된 파일명을 모르기 때문에 db에서 조회해야함.
- 브라우저에게 전달한 내용이 HTML에 뿌리는게 아니라 파일을 다운로드 할 수 있는 창을 띄울 수 있게 요청해야함. ( 행동방식을 이끌어내는건 헤더값)

```java
@WebServlet("/board/fileDownload")
public class BoardFileDownloadServlet extends HttpServlet {
	private static final long serialVersionUID = 1L;
	private BoardService boardService = new BoardService();
	
	/**
	 * @see HttpServlet#doGet(HttpServletRequest request, HttpServletResponse response)
	 */
	protected void doGet(HttpServletRequest request, HttpServletResponse response) 
											throws ServletException, IOException {
		// 1. 사용자입력값처리
		int no = Integer.parseInt(request.getParameter("no"));

		// 2. 업무로직
		Attachment attach = boardService.findAttachmentByNo(no); // 한건의 Attachment조회
		System.out.println(attach);
		
		String saveDirectory = getServletContext().getRealPath("/upload/board");
		String originalFilename = attach.getOriginalFilename();
		String renamedFilename = attach.getRenameFilename();
		
		// 3. 응답처리 (지금까지한것과 조금 다름 html 돌려주는게 아니라 file)
		// 파일을 읽어서(input) 응답메세지에 쓴다(output)
		HelloMvcUtils.fileDownload(response, saveDirectory, originalFilename, renamedFilename);
	}
```

```java
public Attachment findAttachmentByNo(Connection conn, int no) {
		PreparedStatement pstmt = null;
		ResultSet rset = null;
		Attachment attach = null;
		String sql = prop.getProperty("findAttachmentByNo");
		
		try {
			// select * from attachment where no = ?
			pstmt = conn.prepareStatement(sql);
			pstmt.setInt(1, no);
			rset = pstmt.executeQuery();
			if(rset.next()) 
				attach = handleAttachmentResultSet(rset);
				
		} catch (SQLException e) {
			throw new BoardException("첨부파일 조회 오류", e);
		} finally {
			close(rset);
			close(pstmt);
		}
		return attach;
	}

private Attachment handleAttachmentResultSet(ResultSet rset) throws SQLException {
		Attachment attach = new Attachment();
		attach.setNo(rset.getInt("no"));
		attach.setBoardNo(rset.getInt("board_no"));
		attach.setOriginalFilename(rset.getString("original_filename"));
		attach.setRenameFilename(rset.getString("renamed_filename"));
		attach.setRegDate(rset.getDate("reg_date"));
		return attach;
	}
```

### 공통 사용 : HelloMvcUtil

---

- 기본스트림 - 대상과 연결
    - 연결하는 스트림을 새로 생성하지 않아도 response가 가지고 있음
- 보조스트림 - 기본스트림과 연결. 보조스트림을 제어
- `response.setContentType` 메소드 2진파일을 보낼때 사용하는 타입
- `response.setHeader("Content-Disposition",파일명)` : 첨부파일 다운로드요청
- **** 쓰기 작업하기 전에 헤더작성**

```java
public static void fileDownload(HttpServletResponse response, String saveDirectory, String originalFilename,
		String renamedFilename) throws UnsupportedEncodingException, IOException, FileNotFoundException {
	// 헤더작성
	// 기본적으로 text/html을 자주 사용했음
	response.setContentType("application/octet-stream");//응답데이터 타입
	// Content-Disposition 첨부파일인 경우, 브라우저 다운로드(Save as)처리 명시
	// 이렇게 써줘야 브라우저가 파일을 저장해야하는지 알아먹음
	String resFilename = new String(originalFilename.getBytes("utf-8"), "iso-8859-1"); // tomcat 기본인코딩
	// 헤더에 키, 벨류 형식으로 전달
	response.setHeader("Content-Disposition", "attachment;filename=" + resFilename);
	System.out.println("resFilename = " + resFilename);
	
	
	//파일을 읽어서 (input) 응답메세지에 쓴다(output)
	File file = new File(saveDirectory, renamedFilename);
	
	// 기본스트림 - 대상과 연결
	// 보조스트림 - 기본스트림과 연결. 보조스트림을 제어
	// 입출력 관련 IOE 예외를 던지는데 메소드시그니처에서 던지고 있음
	// 자원반납은 당연히 됨...? 
	try(BufferedInputStream bis = new BufferedInputStream(new FileInputStream(file));
		BufferedOutputStream bos = new BufferedOutputStream(response.getOutputStream());
		)
	{
		byte[] buffer = new byte[8192]; // 버퍼단위로 읽어서
		int len = 0; // 읽어낸 byte수
		while((len = bis.read(buffer)) != -1) {// 읽어낸 개수가 양수라면
			bos.write(buffer, 0, len); // buffer의 0번지부터 len(읽은 개수)만치 출력
		}
	}
}
```

- **.getBytes("utf-8"), "iso-8859-1"** : 한글파일명도 읽을 수 있게 함
- network에서 확인할 때는 브라우저가 읽을 수 있게 iso-8859-1 로 읽게 하고 
파일을 실제로 다운받을 때 utf-8로 인코딩되어서 한글이 깨지지 않는다.
- HTTP 헤더부분이라서 utf-8이 안되고 바디에서 작동함.
