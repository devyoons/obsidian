### 협업하는 방법 2가지

#### 1. fork - pull request

![[02 - 학습/KH 교육과정 2022/수업 필기/첨부/045aabaf_Untitled.png]]

![[02 - 학습/KH 교육과정 2022/수업 필기/첨부/4f023557_Untitled.png]]

**open source —- fork and pull request(contributor 소스코드에 기여한 사람)**

: 일면식이 없어도 협업할 수 있는 방법

: 찍어서 내 저장소에 옮긴다. ( repo 저장소에 있는 파일을 dev a로 옮긴다)

: 변경사항을 pull request 요청 

: 어떤 코드가 수정되었는지 확인 후 실제 반영할 수도 있고 안할수도 있음

#### 2. github collaboration(사용할 방식)

**team —- collaborator invitation and branch** 

![[02 - 학습/KH 교육과정 2022/수업 필기/첨부/6dde65d4_Untitled.png]]

: 참여한 팀원들에게 각각 브랜치를 준다.

: 팀원은 자기 브랜치에서만 작업을 하고 완성된 기능은 마스터로 머지한다.

**: 마스터브랜치로 온전한 코드, 완성된 코드만 가지고 가는게 중요하다.**

1. 지역별 저장소(내파일) ————> 원격저장소에 
**보내는게 [push]** 
**가져오는 행위가 [fetch]  
pull + merge= [pull]**

![[02 - 학습/KH 교육과정 2022/수업 필기/첨부/81b2450d_Untitled.png]]

![[02 - 학습/KH 교육과정 2022/수업 필기/첨부/4f67b602_Untitled.png]]

![[02 - 학습/KH 교육과정 2022/수업 필기/첨부/4f67b602_Untitled.png]]

- remote repository와 local repository는 1대1로 대응
- local에 작업브랜치가 따로 존재한다.
- 원격저장소에도 동일한 브랜치를 관리하도록한다.
- local저장소에는 원격추적브랜치 즉, **원격저장소에서 관리하는 브랜치를 읽기 전용으로 볼 수 있다.**
    - remote tracking (read only)
        - origin/master
        - origin/animal …
- `fetch` 는 가져오는 행위지만 원격추적브랜치에 따로 저장된 후에 `merge`로 온전히 가져오는 거임.

#### 3명의 개발자가 협업하는 예시

- 팀장1명 팀원2명 나눠서 작업하는게 좋음.
- 각각의 지역저장소에는 master가 존재함(main도 동일한말임)
- 깃헙원격에도 master가 있고 팀원별로 브랜치가 존재한다.

홍팀장 신사 세종 팀원

![[02 - 학습/KH 교육과정 2022/수업 필기/첨부/05796329_Untitled.png]]

푸시(보낼때)는 내 브랜치로 ~~ 풀(가져올때)은 마스터로 ~~

- 홍팀장이 신사와 세종을 초대
- 브랜치가 이름별로 존재하게 됨.
- 각각의 지역저장소에는 master가 있을 예정
- 원격저장소에 **세종는 세종브랜치에만 push** / **신사는 신사브랜치에만 push** …
- 원격저장소에 **내 브랜치를 master로 반영해달라고 요청**하는게 `pull request`
- 원격저장소 master에 홍작업 pull request한 후엔 master에서 홍작업이 반영이 되어있을예정 그럼 그걸 지역저장소로 pull하면 홍작업이 반영된걸 확인 할 수 있음
