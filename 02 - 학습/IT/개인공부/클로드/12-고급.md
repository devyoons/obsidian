# 12. 고급 — 자동화, GitHub Actions, 병렬 작업

## 학습 목표

- `claude -p`로 스크립트·배치 작업에 Claude를 끼워 넣는다.
- GitHub Actions에 Claude를 붙여 PR과 이슈에서 `@claude`로 부른다.
- worktree, 클라우드 세션으로 여러 작업을 동시에 돌린다.

## 설명

### 비대화형 실행(헤드리스)

```powershell
claude -p "질문"                              # 답만 출력
claude -p "질문" --output-format json         # 결과를 JSON으로(text, json, stream-json)
Get-Content error.log | claude -p "원인 요약" # 파이프 입력
claude -p "작업" --max-turns 5                # 반복 횟수 제한
claude -p "작업" --permission-mode acceptEdits
```

자동화에서는 `--permission-mode dontAsk`와 settings.json의 허용 규칙을 같이 써서, **미리 허락한 것만** 하게 만드는 것이 안전합니다.

### GitHub Actions

1. 저장소 폴더에서 `gh auth login`이 되어 있는지 확인합니다.
2. 세션에서 `/install-github-app`을 실행합니다. Claude GitHub App을 설치하고, 시크릿(`ANTHROPIC_API_KEY` 또는 `CLAUDE_CODE_OAUTH_TOKEN`)을 넣고, 워크플로 파일이 담긴 PR을 엽니다.
3. 그 PR을 병합한 뒤, 이슈나 PR 댓글에 `@claude`를 적어 부릅니다.
4. 워크플로는 `anthropics/claude-code-action@v1`을 씁니다.

### 병렬 작업

- **worktree**(07단계): `claude -w 이름`으로 작업마다 따로 된 폴더.
- **데스크톱 앱 여러 세션**: 세션을 나란히 띄워 각자 다른 일을 맡깁니다.
- **클라우드 세션**: 데스크톱 앱에서 환경을 Cloud로 고르면 Anthropic 서버에서 돌고, 앱을 닫아도 계속 일합니다. 로컬 폴더가 아니라 저장소를 기준으로 동작합니다.

### 최종 정리: 공식 모범 사례 여섯 가지

1. Claude가 못 보는 것을 알려 준다. CLAUDE.md는 짧게, 절차는 스킬로.
2. Claude가 돌려 볼 확인 수단(테스트, 스크린샷, 예상 출력)을 준다. Stop 훅으로 강제할 수 있다.
3. 꼭 지킬 규칙은 훅이나 거부 규칙으로. CLAUDE.md는 권고일 뿐이다.
4. 기본값을 의도적으로 바꾼다: 권한 모드(`Shift+Tab`), 모델과 effort(`/model`, `/effort`).
5. 일찍 방향을 잡는다: `Esc`로 멈추고, `/rewind`로 되돌리고, 작업 사이엔 `/clear`, 복잡하면 계획 모드.
6. 맡겨 두고 돌린다: 스크립트의 `claude -p`, 예약 작업, worktree 병렬 세션.

## 실습 과제

### 실습 1. 로그 요약 스크립트

`practice\scripts\summarize-log.ps1`:

```powershell
param([string]$LogPath)
Get-Content $LogPath -Tail 200 | claude -p "이 로그에서 오류만 골라 원인별로 묶고, 각각 한 줄로 요약해. 마크다운 표로." --max-turns 3
```

```powershell
.\scripts\summarize-log.ps1 -LogPath .\server.log
```

로그 파일이 없으면 Claude에게 가상의 로그를 만들어 달라고 합니다.

### 실습 2. JSON 출력 다루기

```powershell
claude -p "package.json의 dependencies 이름만 배열로 답해" --output-format json | ConvertFrom-Json
```

출력 구조를 보고 답이 어느 필드에 들어 있는지 확인합니다.

### 실습 3. GitHub Actions(GitHub 저장소가 있을 때)

```text
/install-github-app
```

만들어진 PR을 병합한 뒤, 이슈 하나를 만들고 댓글로 요청합니다.

```text
@claude 이 이슈 내용대로 README에 설치 방법을 추가하는 PR을 만들어 줘.
```

### 실습 4. 병렬 작업 미니 프로젝트

할 일 API에 세 기능(태그, 페이지 나누기, 통계 API)을 붙입니다. 계획 모드로 계획을 세운 다음, 서로 다른 파일을 건드리는 작업을 worktree 세션이나 데스크톱 앱 세션 세 개로 나눠 동시에 돌리고, 마지막에 병합과 전체 테스트를 합니다.

### 실습 5. 나만의 작업 키트 정리

지금까지 만든 것을 모아 둡니다.

- `~/.claude/CLAUDE.md`: 나의 공통 규칙(짧게)
- `~/.claude/skills/`: 자주 쓰는 절차 스킬 2~3개
- `~/.claude/agents/`: 리뷰어 등 서브에이전트
- `~/.claude/settings.json`: 허용·거부 규칙, 훅

## 확인 체크리스트

- `claude -p`를 쓰는 스크립트를 하나 만들어 돌렸다.
- `--output-format json` 결과를 파싱했다.
- (선택) GitHub에서 `@claude`로 PR을 받아 봤다.
- 세 개 이상의 작업을 병렬로 돌리고 병합했다.
- 모범 사례 여섯 가지를 내 말로 설명할 수 있다.
- 나만의 CLAUDE.md, 스킬, 서브에이전트, 설정을 갖췄다.
