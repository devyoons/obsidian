# 09. 슬래시 명령, 스킬, 플러그인

## 학습 목표

- 자주 쓰는 내장 슬래시 명령을 안다.
- 나만의 스킬(SKILL.md)을 만들어 `/이름`으로 부른다.
- 플러그인 마켓플레이스에서 플러그인을 찾아 설치한다.

## 설명

### 자주 쓰는 내장 명령

| 명령 | 하는 일 |
|---|---|
| `/help` | 도움말 |
| `/clear` | 대화 비우고 새로 시작(별칭 `/reset`, `/new`) |
| `/compact [지시]` | 대화를 요약해 컨텍스트 줄이기 |
| `/context` | 컨텍스트를 무엇이 차지하는지 보기 |
| `/usage` | 사용량·비용 보기(`/cost`는 별칭) |
| `/model` | 모델 고르기 |
| `/effort` | 생각 깊이 정하기 |
| `/plan [설명]` | 계획 모드로 시작 |
| `/permissions` | 허용·거부 규칙 |
| `/init`, `/memory` | CLAUDE.md 만들기, 메모리 편집 |
| `/resume`, `/rename` | 지난 세션 이어 가기, 세션 이름 바꾸기 |
| `/rewind` | 체크포인트로 되돌리기 |
| `/export [파일]` | 대화 내보내기 |
| `/security-review` | 변경 사항 보안 점검 |
| `/agents`, `/mcp`, `/hooks`, `/plugin` | 서브에이전트, MCP, 훅, 플러그인 관리 |
| `/status`, `/doctor` | 상태, 진단 |
| `/install-github-app` | GitHub Actions 연동(12단계) |

`/`만 입력하면 지금 쓸 수 있는 명령 목록이 뜹니다. 버전에 따라 바뀌니 목록을 직접 확인하는 습관을 들이세요.

### 스킬 = 내가 만드는 명령 + 자동 절차

스킬은 반복하는 절차를 적어 둔 `SKILL.md`입니다. `/이름`으로 직접 부르거나, 설명(description)이 상황과 맞으면 Claude가 알아서 씁니다.

| 위치 | 범위 |
|---|---|
| `.claude/skills/<이름>/SKILL.md` | 이 프로젝트 |
| `~/.claude/skills/<이름>/SKILL.md` | 내 모든 프로젝트 |
| 플러그인 안 `skills/<이름>/SKILL.md` | `/플러그인:스킬`로 부름 |

예전 방식인 `.claude/commands/*.md`도 계속 동작하며 스킬로 합쳐졌습니다. 이름이 겹치면 스킬이 이깁니다.

주요 앞머리(frontmatter) 필드:

- `name`, `description`: 이름과 "언제 쓰는지" 설명(자동 호출의 기준)
- `argument-hint`: 인자 안내
- `disable-model-invocation: true`: 내가 부를 때만 실행(자동 호출 막기)
- `allowed-tools`: 이 스킬이 쓸 수 있는 도구 제한
- `model`, `effort`: 이 스킬에서 쓸 모델·생각 깊이

본문에서 `$ARGUMENTS`(전체 인자), `$0`·`$1`(순서별 인자)를 쓸 수 있습니다.

### 플러그인

스킬, 서브에이전트, 훅, MCP 서버를 묶어 나눠 주는 꾸러미입니다.

- `/plugin`: 메뉴 열기(찾기, 설치, 켜고 끄기)
- `/plugin marketplace add owner/repo`: 마켓플레이스 추가(git URL, 로컬 경로도 가능)
- `/plugin install 이름@마켓플레이스`: 설치(범위 고르는 창이 뜸)
- 터미널에서: `claude plugin install 이름@마켓플레이스 --scope user`
- 공식 마켓플레이스 `claude-plugins-official`은 처음 대화형 세션을 열 때 자동으로 추가됩니다.
- 데스크톱 앱: 입력창 옆 `+` 버튼 > Add plugins.

## 실습 과제

### 실습 1. 내장 명령 둘러보기

```text
/
```

목록에서 위 표에 없는 명령 세 개를 골라 `/help`나 질문으로 쓰임을 알아봅니다.

### 실습 2. 첫 스킬 만들기

할 일 API 프로젝트에서 `.claude/skills/api-check/SKILL.md`를 만듭니다. Claude에게 시켜도 됩니다.

```markdown
---
name: api-check
description: API 엔드포인트를 새로 만들거나 고친 뒤 점검할 때 쓴다
argument-hint: [엔드포인트 경로]
---

$ARGUMENTS 엔드포인트를 점검한다.

1. 해당 라우트 코드와 테스트 파일을 찾는다.
2. 성공, 잘못된 입력(400), 없는 자원(404) 경우의 테스트가 있는지 확인하고 없으면 추가한다.
3. `npm test`를 돌려 결과를 보고한다.
4. 문제 목록을 심각도 순으로 정리한다.
```

```text
/api-check /todos/:id
```

### 실습 3. 자동 호출 확인

`/clear` 뒤 스킬 이름을 말하지 않고 요청합니다.

```text
PATCH /todos/:id 엔드포인트를 새로 만들어 줘.
```

Claude가 api-check 스킬을 알아서 쓰는지 봅니다. 쓰지 않으면 description을 더 구체적으로 고쳐 다시 해 봅니다.

### 실습 4. 플러그인 설치

```text
/plugin
```

공식 마켓플레이스에서 관심 있는 플러그인 하나를 골라 user 범위로 설치하고, 들어 있는 스킬을 한 번 써 봅니다.

## 확인 체크리스트

- 내장 명령 열 개 이상의 쓰임을 안다.
- SKILL.md를 만들어 `/이름 인자`로 실행했다.
- description만으로 스킬이 자동 호출되는 것을 확인했다.
- `disable-model-invocation`을 언제 쓰는지 안다.
- 마켓플레이스에서 플러그인을 하나 설치해 써 봤다.
