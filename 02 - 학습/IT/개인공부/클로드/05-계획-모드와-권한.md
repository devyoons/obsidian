# 05. 계획 모드와 권한 모드

## 학습 목표

- 권한 모드 여섯 가지의 차이를 알고 작업에 맞게 고른다.
- 계획 모드로 "먼저 계획, 승인 후 실행" 흐름을 쓴다.
- settings.json에 허용·거부 규칙을 넣어 반복 승인을 줄인다.

## 설명

### 권한 모드

| 모드(설정값) | 앱 표시 | 하는 일 | 언제 |
|---|---|---|---|
| `default` | Manual | 파일 수정·명령마다 물어봄 | 처음, 낯선 코드 |
| `acceptEdits` | Accept edits | 파일 수정은 자동 승인, 명령은 물어봄 | 믿을 만한 작업 |
| `plan` | Plan | 읽고 조사만, 고치지 않고 계획을 냄 | 큰 변경 전 |
| `auto` | Auto | 백그라운드 분류기가 위험한 동작만 걸러 냄 | 오래 맡길 작업(쓸 수 있을 때만) |
| `dontAsk` | — | 묻는 대신 거부. 미리 허용한 것만 실행 | 자동화 |
| `bypassPermissions` | Bypass permissions | 묻지 않고 전부 실행 | 격리된 환경에서만 |

- CLI: `Shift+Tab`으로 모드를 돌아가며 바꿉니다. 시작할 때 정하려면 `claude --permission-mode plan`.
- 데스크톱 앱: 입력창 근처의 모드 선택기에서 고릅니다. 클라우드 세션은 Accept edits, Plan, Auto만 됩니다.
- `bypassPermissions`는 되돌릴 수 없는 명령도 묻지 않고 실행합니다. 컨테이너나 VM 같은 격리 환경이 아니면 쓰지 마세요.

### 계획 모드

계획 모드에서는 Claude가 코드를 읽고 조사만 한 뒤 계획을 보여 줍니다. 승인하면 실행으로 넘어갑니다.

- 들어가기: `Shift+Tab`으로 상태 줄에 `⏸ plan mode on`이 보일 때까지, 또는 `/plan 설명`.
- 좋은 흐름: **조사 → 계획 → 승인 → 구현 → 확인**.
- 모델 별칭 `opusplan`을 고르면 계획은 Opus, 실행은 Sonnet이 맡습니다(11단계 비용 절약).

### 허용·거부 규칙

자주 승인하는 명령은 미리 허용하고, 위험한 명령은 막아 둡니다. `/permissions`에서 화면으로 고치거나 settings.json을 직접 씁니다.

| 파일 | 범위 |
|---|---|
| `~/.claude/settings.json` | 나의 모든 프로젝트 |
| `.claude/settings.json` | 프로젝트(팀 공유) |
| `.claude/settings.local.json` | 프로젝트, 나만(git 제외) |

```json
{
  "permissions": {
    "allow": [
      "Bash(npm run test *)",
      "Bash(git status)",
      "Bash(git diff *)"
    ],
    "deny": [
      "Bash(git push *)",
      "Read(./.env)"
    ]
  }
}
```

MCP 도구를 허용할 때는 `mcp__<서버이름>__` 접두어를 그대로 씁니다. 예: `mcp__github__get_*`.

## 실습 과제

04단계의 할 일 API 프로젝트에서 진행합니다.

### 실습 1. 계획 모드로 기능 설계

`Shift+Tab`으로 plan 모드에 둔 뒤:

```text
할 일에 마감일(dueDate)을 추가하고 마감 지난 항목만 보는 API를 만들고 싶어.
바꿔야 할 파일, 순서, 테스트 계획을 정리해 줘.
```

계획을 읽고 한 가지를 고쳐 달라고 한 뒤(예: "마감일은 ISO 문자열로"), 승인해서 실행합니다.

### 실습 2. 모드 비교

같은 작은 작업을 `default`와 `acceptEdits`로 한 번씩 시켜 승인 횟수 차이를 느껴 봅니다.

```text
README.md에 실행 방법 섹션을 추가해 줘.
```

### 실습 3. 허용·거부 규칙

```text
/permissions
```

`Bash(npm run test *)`를 허용에, `Bash(git push *)`를 거부에 넣습니다. 그다음 확인합니다.

```text
테스트를 돌려 줘. 그리고 git push도 해 봐.
```

테스트는 묻지 않고 돌고, push는 막히는지 봅니다.

## 확인 체크리스트

- [ ] 여섯 가지 권한 모드를 상황별로 고를 수 있다.
- [ ] `Shift+Tab`(또는 앱의 모드 선택기)으로 모드를 바꿨다.
- [ ] 계획 모드에서 계획을 받아 고치고 승인했다.
- [ ] settings.json 세 곳의 차이를 안다.
- [ ] 허용 규칙으로 승인 없이 테스트를 돌렸고, 거부 규칙으로 push를 막았다.
