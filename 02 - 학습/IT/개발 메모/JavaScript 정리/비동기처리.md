- 비동기 처리
    - Timer API
        - 일반함수는 동기적으로 처리되므로, `foo`가 리턴한 값을 `resultSync`에 대입할 수 있다.
            - `foo`를 호출하고, 처리가 완료될때까지 기다린다. `동기적 처리`
        - Timer API함수(`setTimeout`, `setInterval`)은 비동기적으로 처리되므로 `undefined`가 출력된다.
            - callback함수의 실행을 기다리지 않는다. `비동기적 처리`
        
```jsx
<button id="btn1">Async - Timer</button>
<script>
/**
 * 비동기처리함수 - Timer API
 */
btn1.onclick = () => {
  // 동기식처리
  let resultSync = foo();
  console.log(resultSync); // 실행결과 foo - 100

  // 비동기식처리
  let resultAsync;
  // Timer API 함수들은 호출과 동시에 background(Web APIs)에 처리를 위임한다.
  setTimeout(() => {
    resultAsync = 100;
  }, 0);
	console.log(resultAsync); // undefined
};

const foo = () => {
  console.log('foo');
  return 100;
}
```

- DOM관련 처리

`document.head.append(script);` DOM관련 처리가 비동기적으로 처리되므로, 실제 script태그의 load되는 것을 기다리지 않고, 리턴해서 `bar`를 호출, 오류가 발생한다.

```jsx
	bar(); // Uncaught ReferenceError: bar is not defined
};

const loadScript = (path, callback) => {
  const script = document.createElement('script');
  script.src = path;
  document.head.append(script); // 비동기처리
};
```
```jsx
</script>
```

- Promise
    - Promise란
        
```jsx
<button id="btn1">basics</button>
<script>
/**
 * Promise
 * - 기존 callback함수를 통한 비동기처리(Callback Hell)를 개선하기 위한 문법
 * - producer/consumer 코드를 연결
 *    - producer(비동기처리가 포함된 코드)
 *    - consumer(비동기완료후 실행할 코드)
 * 
 * 속성
 * - status
 *    - pending -> settled (fulfilled(이행) / rejected(거부))
 * 
 * - result
 *    - undefined -> value(이행시) / error객체(거부시)
 * 
 */
btn1.onclick = () => {
  // resolve 이행시 호출할 콜백함수. then에서 전달.
  // reject 거부시 호출할 콜백함수. catch에서 전달.
  const promise = new Promise((resolve, reject) => {
    const num = Math.floor(Math.random() * 2);  // 0 1
    console.log("producing.....", num);

    try {
      if(!num) 
				throw new Error("오류 발생"); // num이 0인 경우
      resolve(num); // 이행 콜백호출
    } catch(e){
      reject(e); // 거부 콜백 호출
    }
  });
  console.log(promise); 

  promise
    .then((value) => {
      console.log('result : ', value);
    })
    .catch((err) => {
      console.error('result : ', err);
    });
};
</script>
```

- Promise Chain

<aside>
💡 Promise의 then메소드는 암묵적으로 promise객체를 만들어 반환하므로, then을 계속 이어서 작성할 수 있다. 
`Callback Hell` 에 이은 `Then Hell`…

</aside>

```jsx
<button id="btn3">Promise Chain</button>
<script>
/**
 * Promise Chain
 * - 1. 암묵적 chain : then의 resolve콜백에서 리턴값이 없다면, 암묵적으로 promise객체 반환 
 *      - resolve 콜백에서 특정값을 리턴한다면, 암묵적 promise객체의 result값으로 사용된다.
 * - 2. 명시적 chain : then의 resolve콜백에서 다시 promise객체를 반환후, then메소드로 chaining 가능.
 */
btn3.onclick = () => {
  getTimeoutPromise("안녕", 1000)
    .then((msg) => {
      console.log(msg);
      return getTimeoutPromise("잘가", 1000);
    })
    .then((msg) => {
      alert(msg);
    });
};

/**
 * millis이후에 이행(resolve)되는 Promise객체를 반환
 */
const getTimeoutPromise = (msg, millis) => {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve(msg);
    }, millis);
  });
};
</script>
```

<aside>
💡 then에서 전달한 callback함수에서 <u>Promise가 아닌 값을 반환</u>한다면 암묵적으로 생성된 Promise객체의 result값으로 사용되고, 다음 then의 callback에서 인자로 사용할 수 있다.

</aside>

```jsx
<button id="btn4">Promise Chain - 값반환</button>
<script>
btn4.onclick = () => {
  new Promise((resolve) => {
    resolve(1);
  })
  .then((value) => {
    console.log(value); // 1
    return value * 2; // 암묵적 Promise객체의 resolve(value)의 result(value)값이 된다. 
  })
  .then((value) => {
    console.log(value); // 2
    return value * 2;
  })
  .then((value) => {
    console.log(value); // 4
    return value * 2;
  });
};
</script>
```

프로미스는 자바스크립트 비동기 처리에 사용되는 객체이다.

자바스크립트의 비동기 처리란?

- ‘ **특정 코드의 실행이 완료될 때까지 기다리지 않고 다음 코드를 먼저 수행하는 자바스크립트의 특성**’을 의미
- **비동기적인것을 수행할 때 콜백함수 대신에 사용하는것.**
    - callback hell을 제거, 아래로 코드를 연이어 작성할 수 있다.(가독성, 유지보수좋음)
- **`Primise`**는 **producer와 consumer코드를 연결해주는 객체**
    - **producer(생산자) code** 비동기 : 제작 코드 : 정보를 제공하는
    - **consumer(소비자) code** 콜백 : 소비 코드 : 정보를 소비하는
- then 프라미스를 리턴하므로 이후 실행코드는 다시 then절 작성가능하다.

##### 1. Promise 만들기

- **새로운 Promise 를 만드는 순간 전달한 콜백함수가 바로 실행된다.**
    - 네트워크를 통신하는 코드를 작성했다면 Promise가 만들어지는 순간 바로 네트워크 통신을 수행하게 된다 .
    - 만약 네트워크 요청을 사용자가 요구했을 때만 네트워크 요청을 해야한다면 이렇게 작성하면 바로 실행된다는 점 유의하기

##### promise 문법

```jsx
const promise = new Promise((resolve, reject) => {
	console.log('Producing.....');
}
```

```jsx
const promise = new Promise(function(resolve, reject) {
  // executor (제작 코드, '가수')
});
```

`new Promise`에 전달되는 함수는 *executor(실행자, 실행 함수)* 라고 부릅니다. 

executor는 `new Promise`가 만들어질 때 자동으로 실행되는데, 결과를 최종적으로 만들어내는 제작 코드를 포함합니다. 위 비유에서 '가수’가 바로 executor입니다.

- `resolve(value)` : 일이 성공적으로 끝난 경우 그 결과를 나타내는 `value`와 함께 호출
    - resolve 코드예시

```jsx
const promise = new Promise(function(resolve, reject) {
  // 프라미스가 만들어지면 executor 함수는 자동으로 실행됩니다.

  // 1초 뒤에 일이 성공적으로 끝났다는 신호가 전달되면서 result는 '완료'가 됩니다.
  setTimeout(() => resolve("완료"), 1000);
});
```

![[02 - 학습/KH 교육과정 2022/수업 필기/첨부/8bc9c099_Untitled.png]]

- `reject(error)` : 에러 발생 시 에러 객체를 나타내는 `error`와 함께 호출
    - reject 코드예시

```jsx
const promise = new Promise(function(resolve, reject) {
  // 1초 뒤에 에러와 함께 실행이 종료되었다는 신호를 보냅니다.
  setTimeout(() => reject(new Error("에러 발생!")), 1000);
});

// 1초 후 reject(...)가 호출되면 promise의 상태가 "rejected"로 변합니다.
```

##### 2. promise의 3가지 상태(states)

- `new promise()` 로 promise를 생성하고 종료될 때까지 3가지 상태를 갖는다.
    - Pending : 비동기 처리 로직이 아직 완료되지 않은 상태
    - Fulfilled : 비동기 처리가 완료되어 프로미스가 결과 값을 반환해준 상태
    - Rejected : 비동기 처리가 실패하거나 오류가 발생한 상태

    ![[02 - 학습/KH 교육과정 2022/수업 필기/첨부/aba9290b_Untitled.png]]

    | status | pending(대기) | 정상처리 fullfilled (이행) |
    | --- | --- | --- |
    |  |  | 오류 rejected(실패) |
    | result | undefined | 정상처리시 value |
